## Phase 1: Critical Bug Fixes & Stability (Immediate)

- [x] **1.1 Fix Seerr ↔ Plex connection timeout**
  - **Issue**: Seerr logs `connect ETIMEDOUT 192.168.50.161:32400` every 5 minutes because of an old host IP.
  - **Action**: In `provision/overseerr/settings.json` (or via Seerr Web UI under *Settings -> Plex*), update `ip` from `192.168.50.161` to `plex` (Docker internal container DNS).
  - **Verification**: Run `docker logs --tail 20 seerr` and verify Plex library scan succeeds without timeout.

- [x] **1.2 Mount `/dev/shm:/transcode` for Plex**
  - **Issue**: Plex preferences specify `TranscoderTempDirectory="/transcode"`, but no `/transcode` volume is mounted in `docker-compose.yml`. Transcode chunks write into the root SSD container overlayfs.
  - **Action**: Add dedicated 2G tmpfs mount (`/transcode:size=2G,mode=0777`) to `plex` service.
  - **Verification**: Verified inside container with `df -h /transcode` (tmpfs 2.0G mounted, 0% used).

- [x] **1.3 Fix FlareSolverr runaway container storage leak (Reclaim 2.2 GB)**
  - **Issue**: FlareSolverr writable container layer has grown to **2.22 GB** due to accumulated Chromium `/tmp` cache and Widevine updates.
  - **Action**: Add `tmpfs: - /tmp:size=256M` and `mem_limit: 512m` to the `flaresolverr` service in `docker-compose.yml`. Recreate container with `docker compose up -d --force-recreate flaresolverr`.
  - **Verification**: Size dropped from 2.22 GB to 22.4 MB; tmpfs 256M active on `/tmp`; HTTP health check returned `"FlareSolverr is ready!"`.

- [ ] **1.4 Configure Plex connection webhooks in Radarr & Sonarr**
  - **Issue**: Neither app notifies Plex when downloads complete. Because `/mnt/storage` is an NTFS filesystem (`ntfs3`), Linux kernel inotify events do not reliably trigger automatic Plex scans.
  - **Action**: In Radarr & Sonarr, go to **Settings -> Connect -> Add (+) -> Plex Media Server**, set host to `plex`, port `32400`, enter token, and enable update on import/rename.
  - **Verification**: Click "Test" in Radarr/Sonarr connection settings and verify a green checkmark.

- [ ] **1.5 Clean and quiet down stack updates (`update_stack.sh`)**
  - **Issue**: `update.log` is 442 KB of raw terminal carriage return escape sequences generated by non-interactive `docker compose pull`.
  - **Action**: Add `--quiet` to `docker compose pull` in `update_stack.sh` and truncate/rotate `update.log`.
  - **Verification**: Run `update_stack.sh` manually and ensure clean, concise logging.

## Phase 2: Hardware Acceleration & Playback Performance

- [ ] **2.1 Pass Intel QuickSync GPU (`/dev/dri`) into Plex**
  - **Issue**: Plex currently transcodes 100% on the dual-core CPU because the Intel HD Graphics 4600 integrated GPU (`/dev/dri/renderD128`) is not mapped to the container.
  - **Action**: In `docker-compose.yml`, add `devices: - /dev/dri:/dev/dri` and `group_add: ["990", "44"]` to Plex.
  - **Verification**: Verify `/dev/dri` exists inside container (`docker exec plex ls -la /dev/dri`) and verify hardware transcoding badge `(hw)` appears in Plex Dashboard during an H.264 transcode.

- [ ] **2.2 Automate 5.1 → 2.0 audio downmixing (Replace Windows `.bat` script)**
  - **Issue**: Xiaomi Mi TV (`MiTV-AFMU0`) cannot direct play AAC 5.1 audio. Plex takes 71 seconds to transcode 10 seconds of video (`slothMode="1"`), forcing manual execution of `change_all_5.1_to_2.0.bat`.
  - **Action**: Deploy an automated audio conversion tool (e.g. **Unmanic** container or a Radarr/Sonarr post-import bash script) that checks downloaded media and automatically adds or converts a 2.0 AAC stereo track.
  - **Verification**: Test playback of an automated file on the Xiaomi Mi TV; verify it direct plays both audio and video without buffering.

- [ ] **2.3 Optimize Radarr & Sonarr Custom Formats for Audio Compatibility**
  - **Issue**: Quality profile #4 has `x265` scored at `+1000`. Micro-encodes typically strip stereo tracks and leave only AAC 5.1.
  - **Action**: Add custom format rules to favor releases with AC3/E-AC3 or multi-audio (containing a 2.0 track) or slightly penalize releases with exclusive AAC 5.1.
  - **Verification**: Review interactive search results in Radarr/Sonarr and confirm higher scores for formats compatible with the Mi TV.

- [ ] **2.4 Check Xiaomi Mi TV Plex Client Audio Settings**
  - **Action**: On the Mi TV, navigate to Plex Settings -> Advanced / Audio:
    - Test toggling **Audio Passthrough** (Disabled vs HDMI/Optical).
    - Ensure **Direct Play** and **Direct Stream** are enabled.
  - **Verification**: Verify whether stereo downmix is handled by the TV client directly when passthrough is adjusted.

- [ ] **2.5 Review Prowlarr Indexer Health & Cloudflare Failures**
  - **Issue**: 6 of 9 indexers (1337x, BitSearch, ExtraTorrent, kickasstorrents, RuTracker, Uindex) are currently disabled due to rate limits (429) or Cloudflare blocks.
  - **Action**: Clean up obsolete or duplicate indexers in Prowlarr; verify FlareSolverr proxy assignment for indexers that require Cloudflare bypass.
  - **Verification**: Run "Test All Indexers" in Prowlarr and check for successful response codes.

- [ ] **3.2 Configure Radarr & Sonarr automated cleanup / recycle bin**
  - **Issue**: Logs warn: `Recycle Bin has not been configured, cannot cleanup`.
  - **Action**: In Radarr & Sonarr, configure **Media Management -> File Management -> Recycle Bin** (or enable auto-unmonitor deleted items) to avoid accidental permanent loss or orphaned files.
  - **Verification**: Delete a test movie/episode and check recycle bin behavior.

- [ ] **3.3 Evaluate `TEMP_ROOT` Cross-Device Move vs Atomic Moves**
  - **Context**: Incomplete downloads download to SSD (`/home/kkgmig29/tmp/MediaServerTemp`) and copy across disks to HDD on completion.
  - **Decision**:
    - *Option A (Keep)*: Best for reducing HDD noise and thrashing during active downloading; accepts the cross-device copy penalty on completion.
    - *Option B (Atomic)*: Move `TEMP_ROOT` to `/mnt/storage/MediaServer/incomplete` for instant zero-copy moves and TRaSH guide alignment.
  - **Verification**: Measure disk I/O and import speed upon download completion.

- [ ] **3.4 Review NTFS (`ntfs3`) Mount Options & Long-Term Plan**
  - **Issue**: `/mnt/storage` uses NTFS (`ntfs3`), which has higher CPU overhead on Linux than `ext4` or `btrfs`.
  - **Action**: Check `/etc/fstab` mount flags (ensure `windows_names`, `uid=1000`, `gid=1000`, `iocharset=utf8` are optimized) and plan eventual migration to ext4 if the drive is permanently dedicated to Linux.

- [ ] **3.5 Configure Low-Disk-Space Notifications**
  - **Action**: Set up notification alerts in Seerr/Radarr/Sonarr (via Telegram, Pushbullet, or Discord) when available disk space falls below 50 GB.
